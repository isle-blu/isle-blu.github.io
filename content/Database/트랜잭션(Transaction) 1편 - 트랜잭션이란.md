## 트랜잭션이란?
"Transaction"은 사전적 의미로 거래를 의미한다. 예시로 우리가 은행 송금 거래를 한다고 하자.
우리가 가지고 있는 50,000원을 A 계좌에서 B 계좌 송금한다고 가정했을 때,

<br/>

>[!example]
>1. **A 계좌**에 50,000원을 **B계좌**에 송금한다.
>2. **A 계좌**에서 50,000원이 차감된다.
>3. **A 계좌**에 -50,000원 내역이 출력된다.
>4. **B 계좌**에 50,000원이 가산된다.
>5. **B 계좌**에 +50,000원 내역이 출력된다.

<br/>

위와 같은 ==일련의 과정==을 거치게 될 것이다. 만약 시스템에 문제가 생겨 3번 과정까지만 이뤄지면 무슨 일이 벌어질까? **50,000원이 허공으로 증발한 상황이 된다!** 

따라서 해당 과정은 반드시 과정 ==모두 동시에 성공하거나, 실패해야 한다.==

개발에서 트랜잭션은 데이터 거래 시 위와 같은 불상사를 막기 위한 대안으로, 위에서 말한 일련의 과정(한 번에 수행되어야 할 과정)에 해당한다.

> [!TIP] 트랜잭션
>트랜잭션은 ==한 번의 수행되어야 할 연산의 모음==으로, 데이터베이스와 애플리케이션의 ==데이터 거래 시 안정성을 보호하기== 위한 방법이다.

따라서 트랜잭션은 데이터 작업 시 <u>모든 작업이 성공해야 그 결과를 반영(commit)</u> 하고, 데이터 작업 시 <u>오류가 발생하면 모든 작업을 원상태로 복구(roll back)</u> 한다.


<br/><br/><br/>

## 트랜잭션의 특징 : ACID
트랜잭션의 특징은 크게 4가지로 구분되는 데, 약어로  ACID라고 표현한다.

### Atomicity 원자성
> 원자성은 트랜잭션이 ==DB에 모두 반영되거나, 모두 반영되지 않거나 한다는 것==이다. (All or Nothing)

<br/>

### Consistency 일관성
> 일관성은 ==트랜잭션 처리 결과가 언제나 일관된 상태==로 있어야 한다는 것이다.

트랜잭션의 작업이 진행 중에 <u>참조하고 있는 데이터베이스가 변경되더라도, 처음 참조했던 데이터베이스 그대로</u> 진행된다.

<br/>


###  Isolation 독립성
> 독립성은 여럿의 트랜잭션이 동시에 진행될 경우, ==하나의 트랜잭션이 다른 트랜잭션 연산에 끼어들 수 없는 것==을 말한다.

때문에, 참조하려는 트랜잭션이 완료될 때까지, 해당 트랜잭션을 참조할 수 없다.

<br/>

### Durability  지속성
> 지속성은 하나의 트랜잭션이 완료됐을 때, 그 ==결과가 영구적으로 반영==되어야 한다는 것이다.


<br/><br/><br/>

## 트랜잭션의 연산
트랜잭션에는 **COMMIT**과 **ROLLBACK** 2가지 연산이 있다.  각각에 대해 알아보자

### COMMIT 연산
> 하나의 ==트랜잭션이 끝났다는 것을 선언==하는 연산이다.

트랜잭션이 중간에 문제없이 성공적으로 수행되었다면, 성공 완료를 알려주는 연산으로 그 결과를 DB에 반영하게 된다.

<br/>

### ROLLBACK 연산
> 트랜잭션이 ==실패했을 때, 그것을 선언하고 작업을 취소==하는 연산이다.

트랜잭션이 중간에 문제가 생겨 연산이 처리되지 못한다면, ROLLBACK 연산이 실행되고, 트랜잭션 실패를 선언한다. 그리고 트랜잭션 <u>시작 전과 같은 상태</u>로 DB를 되돌린다.

<br/><br/><br/>

## 트랜잭션의 상태
트랜잭션은 아래 그림과 같은 단계로 진행된다.

<br/>

![[transaction1.png]]

<br/>

각각의 단계는 그 시점의 트랜잭션의 상태를 설명한다.

<br/>

#### 활성(Active)
트랜잭션이 실행되고 <u>동작중인 상태</u>를 말한다.

<br/>

> [!success] 작업 성공 시
> #### 부분 완료(Partially committed)
> 트랜잭션의 연산이 완료되고  **COMMIT** 명령이 도착하고, <u>**COMMIT** 연산 실행 직전 상태</u>를 말한다.
> <br/>
> #### 완료(Committed) 
> **COMMIT** 연산이 실행되고 <u>트랜잭션이 정상적으로 완료</u>된 상태이다.
> 

트랜잭션 연산이 완료됐다고해서 무조건 Commit하는 것은 아니다. 연산이 끝났어도 **COMMIT** 명령어를 날릴 수 없는 상황이라면 **중단**하고 <u>실패 상태로 넘어간다.</u>

<br/>

>[!fail] 작업 실패 시
>#### 실패(Failed)
>오류의 발생으로 <u>트랜잭션이 실패한 상태</u>를 말한다.
><br/>
>#### 철회(Aborted)
>트랜잭션 실행이 취소되고, **ROLLBACK** 연산으로 <u>트랜잭션 실행 이전으로 돌아간 상태</u>를 말한다.

<br/><br/><br/>
