# Getter와 Setter

> private한 속성에 접근하는 방법

이전 시간에 배운 은닉화를 통해, class안에 속성을 가리기로 했다. 하지만, 전처럼 `exam.math`와 같이 변수에 직접 접근할 수 없어, 변수의 값을 **가져오거나 수정할 수가 없게 되었다**. 이것을 대신 해주는 게 **Getter와 Setter**이다.

1. Getter : 객체 안에 속성을 **read**하는 용도로 사용하는 메소드
    - 형태 : `get<read할 속성>()`
    - ex) `exam.getMath()`;
2. Setter : 객체 안에 속성을 **update**하는 용도로 사용하는 메소드
    - 형태 : `set<update할 속성>()`
    - ex) `exam.setMath(int math)`;

```java
public int getMath() {
    return math;
}

public void setMath(int math) {
    this.math = math;
}
```

위와 같이 은닉화된 속성에 접근하기 위한 용도도 있지만, 호출하는 곳에서 읽어오고 수정한다는 것을 좀 더 쉽고 명확하게 이해하고 작성할 수 있다는 장점도 있다.

# 객체 간 관계 - HAS A

class를 만들다보면 속성에 다른 객체가 필요한 경우가 생기거나, 기존 class에서 특정 기능을 수행을 위해 분리해 별도의 class를 만드는 경우가 생긴다. 이런 경우, 두 객체 간의 관계성이 생기게 된다.

> HAS A 한 객체가 다른 객체를 부품으로 가지는 관계를 말한다.

부품으로 사용할 객체를 방법으로는 2가지가 있다.

1. 내부에서 직접 객체 초기화하는 방식
    - 생성자로 처음 객체가 생성될 때 그 내부에서 객체를 직접 초기화하는 경우를 말한다.
    - 이러한 관계를 `Composition HAS A`관계라고 한다.
2. 외부에서 객체를 받아오는 방식
    - 객체를 인자로 받아서 대입하는 방식을 말한다.
    - 이러한 관계를 `Association HAS A`라고 한다.
    - `Association HAS A`에는 **생성자에 인자로 받는 방식**과, **Setter의 인자로 받는 방식**이 있다.

> Dependency Injection(의존성 주입)

위에서 `Association HAS A` 관계에 대해 말했는데, 이처럼 외부에서 속성에 대입할 객체를 받아오는 것을 **Injection(주입)**이라고 한다.

주입을 받은 객체는 받은 객체가 만약 없다면, 서비스를 제공하는데 문제가 발생한다. 즉, 주입된 객체에 의존하는 상황이 된다. 이렇게 의존하게 되는 객체를 주입한다고 해서, **Dependency Injection(의존성 주입)** 줄여서 **DI**라고 표현한다.

외부에서 객체를 받아오는 2가지 방식은 각각 아래와 같이 표현한다.

- Construct DI
- Setter DI

```java
// Composition HAS A
public MenuConsole() { 
    menu = new Menu();
}

// Association HAS A
// Consturcter DI
public MenuConsole(Menu menu) { 
    this.menu = menu;
}

// Setter DI
public void setMenu(Menu menu) {
    this.menu = menu;
}
```
