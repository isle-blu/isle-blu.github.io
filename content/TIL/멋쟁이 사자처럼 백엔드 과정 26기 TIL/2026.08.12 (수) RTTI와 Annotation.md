# RTTI

> **RTTI**는 실행중인 객체가 실제로 어떤 타입인지 알아내는 것을 말한다.

이전까지 객체를 생성할 때, `new` 연산자를 사용해서 객체를 생성했다. 그런데, `new`를 생성하지 않고도, 객체가 만들어지는 경우가 있었는데, 대표적으로 `@WebServlet`과 같이 어노테이션을 사용하는 경우가 있었다.

저렇게 `new`로 직접 class 타입을 지정해주지 않고 어떻게 객체를 생성할 수 있을까? 여기서 적용되는 개념이 RTTI(Run-Time Type Information)이다.

객체를 생성하려는 주체가 개발자 본인이 아닌 경우가 있다. `Tomcat`이 그 중 하나인데, 톰캣은 우리에게 직접 타입을 전달받지 않고, 어노테이션으로 확인 후 서블릿 객체를 생성한다.

위와 같은 경우 톰캣 같이 다른 객체를 생성하고 관리하는 주체가 직접 class 타입을 알아내는 RTTI를 할 수 있어야 하는데, 자바에서는 그것을 다양한 방식으로 제공하고 있다.

> RTTI 예시

1. instanceof — 타입을 물어보기

```java
Animal a = new Dog();

if (a instanceof Dog) {
    System.out.println("이건 Dog다");
}
```

2. 오버라이딩된 메서드 호출 (동적 바인딩)

```java
Animal a = new Dog();
a.sound(); // "멍멍" — 선언 타입(Animal)이 아니라 실제 타입(Dog)의 것이 실행됨
```

3. getClass() — 타입 정보 자체를 조회

```java
Animal a = new Dog();
System.out.println(a.getClass().getName()); // "Dog"
System.out.println(a.getClass().getSuperclass()); // "Animal"
```

4. 리플렉션 — RTTI 정보를 이용해 실제로 조작

```java
Class<?> clazz = Class.forName("com.example.HelloServlet"); // 타입 정보 획득 (RTTI)
Object servlet = clazz.getDeclaredConstructor().newInstance(); // new 없이 생성
Method m = clazz.getMethod("doGet", HttpServletRequest.class, HttpServletResponse.class);
m.invoke(servlet, req, resp); // 메서드도 이름으로 호출
```

이와 같은 방식으로, 개발자가 직접 `new`연산자로 타입을 지정해 객체를 생성하지 않아도, 타입을 직접 찾고 객체를 생성하고 관리할 수 있다.

# Annotation

> 개발자가 아닌 컴퓨터에게 제공하는 주석, 메타데이터

어노테이션은, `@<키워드>`와 같은 형식으로 사용된다. 컴퓨터가 확인하는 주석이자 메타데이터이기에, 그 자체로 실행하는 로직은 없고, 일반적인 주석과 달리 번역한 파일에서도 남아있는 특징이 있다.

어노테이션은 자체적인 로직은 없지만, 컴퓨터을 위한 표식이 되어준다. 예를 들어 `@WebServlet("/hello")`은 실제로 가진 기능은 없지만, 톰캣이 이 어노테이션을 표식으로서 확인하고, url요청에 `/hello`가 왔을 때 해당 서블릿으로 넘기는 것이다.

```java
@WebServlet("/hello")
public class HelloServlet extends HttpServlet { ... }
```
