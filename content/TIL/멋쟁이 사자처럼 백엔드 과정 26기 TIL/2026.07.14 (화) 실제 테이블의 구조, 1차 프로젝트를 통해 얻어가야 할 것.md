# 실제 테이블의 구조

> Supabase에서 생성된 데이터베이스를 보면서 실제 테이블이 어떻게 이뤄져있는 지 보았다.

- 실제 테이블이 생성되면, 논리 설계에서 그린 ERD의 모습과 유사하다.
- 하지만 테이블명과 속성명에서 차이가 있다.
    - PostgreSQL 기준으로 테이블명은 소문자 복수형을 사용한다.
    - 속성명의 경우 소문자를 기본으로 하고, 두 단어 이상인 경우 "_"(언더바)로 연결한다. => `snake_case`를 사용한다.

> 모든 DB에서 snake_case를 사용할까?

- 아니다. 대부분 snake_case로 통용되지만, 그렇지 않은 경우가 있다.
- 아닌 예시(클로드 고맙다!)
    - MySQL : 기본은 PostgreSQL과 비슷하게 snake_case가 흔하지만, 운영체제에 따라 테이블명 대소문자 구분 여부가 달라진다.
    - SQL Server : PascalCase(UserId, CreatedAt)가 상대적으로 흔하게 사용된다.
    - Oracle: 전통적으로 UPPER_SNAKE_CASE(USER_ID)가 관례다.
    - MongoDB : 컬렉션/필드명 모두 camelCase가 표준이다.

# 이번 프로젝트에서 얻어가야할 것

> 다양하게 있을 수 있지만 가장 기억해야할 것은 **AI**에 관해서다.

- AI를 사용하면서, 쉽게 웹 앱을 만들 수 있었다.
- 하지만, AI가 프롬프트를 알아듣지 못하기도 하고, 의도하지 않은 기능이 추가되는 등 문제가 발생했다.
- 이런 방식으로 개발하면 추후 자신도 모르는 문제가 발생할 수 있는 코드가 애플리케이션에 들어갈 수 있다.
- 따라서 AI를 사용만 하는 것이 아닌, 이것을 의도에 맞게 통제하고 개선시킬 수 있는 지 등을 고민할 필요가 있다.
