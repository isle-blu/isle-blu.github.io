# 캡슐화

> 캡슐이란? data(속성)와 동작(method, 서비스, 기능)을 하나로 묶은 것.

하나로 묶는 것이라는 것은 알았지만, 어떤 기준인지 명확하게 정하지 않았다. 캡슐화를 하는 기준은 **"역할"**이다.

> 캡슐화 역할(서비스의 주체)에 따라 속성과 기능을 하나로 묶는 과정을 말한다. 즉 캡슐은 역할자, 개체, 서비스에 대한 책임자이다.

이 역할을 계층에 따라 나눠질 수 있고 주로 이 계층은 4단계로 구분된다.

> UI - 업무(service) - Collection - Entity

위 4단계에서 필요에 따라 더해지거나, 빠질 수 있다.

---

## 캡슐의 변수와 함수

- 변수 : 캡슐의 변수는 속성에 해당한다.
- 함수 : 캡슐의 함수는 제공하는 서비스에 해당한다.

But, 캡슐의 변수와 함수에서 구분되고 객체를 만들지 않고도 전역에서 사용할 수 있게하는 키워드로 `static`이 있다.

> `static` : 전역에서 변수와 함수를 사용할 수 있게 하는 키워드 `static`이 붙으면 전역변수, 함수가 되기 때문에 객체에 종속되지 않고, 어디서든 가져다가 사용할 수 있게된다.(물론, `private`과 같이 지정을 해주면 달라지지만 그건 추후에)

=> 따라서 `static`이 붙어있지 않은 변수와 함수가 해당 캡슐의 진짜 속성이자 서비스이다.

`static`에 구분되기 위해 객체를 다르게 표현하는 단어가 있는데 그게 인스턴스(instance)이다. 아래 표로 정리하면 다음과 같다.

|구분|호출 방식|성격|
|---|---|---|
|static 메소드|ClassName.method() 형태|전역 함수|
|인스턴스 메소드|<객체명>.method() 형태로 호출|객체가 제공하는 서비스|

> 메소드?

- 위에 표를 보면 함수가 아닌 **"메소드"**라는 표현을 사용했다. 메소드는 class 안에 있는 함수를 의미한다.
- 자바의 거의 대부분의 함수는 class 안에 있으므로 많은 자바를 사용하는 개발자들은 메소드라는 표현을 많이 사용한다.

## 책임자

위에서 역할자는 곧 책임자라고 했다. 하지만 우리가 이전에 작성한 코드에서 객체는 책임자로서 제대로 동작하지 않았다.

```java
Exam 영철 = new Exam();        

// 명령을 내리는 우리에게 초기화 작업을 떠넘기고 있다. (나쁜넘)
영철.kor = 30;
영철.eng = 30;
영철.math = 40;
```

그래서 일을 억지로 좀 떠넘겨 봤다.

```java
//main 함수 내부
Exam 영철 = new Exam();        


Exam.init(영철, 30, 30, 40); // 이제 좀 일을 하려고 하는데, 책임감이 부족해 보인다. (조금 나쁜넘)


// class Exam 내부
// 객체를 매개변수로 넘기기 위해 static 메소드를 이용하고 있다. 함수, 동작의 주체가 책임자 본인이 아니다.
public static void init(Exam exam, int kor, int eng, int math) {
    exam.kor = kor;
    exam.eng = eng;
    exam.math = math;
}
```

이제 좀 교육을 시켜서 책임감 있게 일하게 만들어봤다.

```java
Exam 영철 = new Exam();        

영철.init(30, 30, 40); // 이제 진짜 책임을 가지고 직접 일하고 있다.

// class Exam 내부
// static이 없는 서비스에 해당하는 메소드이다.
public void init(int kor, int eng, int math) {
    this.kor = kor;
    this.eng = eng;
    this.math = math;
}
```

위와 같이 직접 객체가 책임을 지고 작업을 하고, 명령의 주체인 우리는 내부 과정을 몰라도 되는 방식이 **"객체 지향"**에 해당한다.
