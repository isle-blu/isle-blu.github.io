# 오늘의 상황

> 오늘은 커뮤니티 글 API(작성·조회·수정·삭제)를 만들어 병합하고, JPA 컬럼명 규칙을 정리했다.

어제 머지한 계획 문서대로 커뮤니티 글 기능을 구현했다. 작성·조회 PR 위에 수정·삭제 PR을 쌓아서 올렸고, 둘 다 리뷰를 반영해서 병합했다. 사이사이 팀원들의 PR도 리뷰했다.

# 오늘의 과정

## 커뮤니티 글 작성·조회 API

> 글 쓰기, 카테고리별 목록, 상세, 카테고리 목록 API를 만들었다.

- `POST /api/v1/posts` : 글 쓰기
- `GET /posts?category=` : 카테고리별 목록 (최신순 커서 페이지)
- `GET /posts/{postId}` : 상세
- `GET /posts/categories` : 카테고리 목록
- 목록과 상세는 로그인 없이 열린다. 만료된 쿠키가 있어도 토큰을 읽지 않는다.

> 리뷰를 받고 고친 것

- 공개 경로를 `/posts/*`에서 `/posts`, `/posts/categories`, `/posts/{postId:\d+}`로 좁혔다. => 와일드카드 대신 **경로 변수 정규식**으로 열 경로만 연다.
- 목록 조건을 요청 객체로 검증한다. `category`가 빠지거나 `size=abc`처럼 잘못 와도 공통 오류 형식의 400이 나간다.
- 제목·본문의 앞뒤 공백은 프론트엔드 `trim()`과 같은 기준으로 지운다.
    - Java의 `strip()`/`trim()`과 JS의 `trim()`은 공백으로 보는 문자가 서로 다르다.
    - 요청 검증과 도메인의 공백 판단이 같은지, 모든 문자로 대조하는 테스트를 더했다.
- 처음 카테고리를 넣을 때 `ON CONFLICT DO NOTHING`을 써서 충돌을 막았다.
- 원격 Docker에서 테스트 42개가 통과했다.

## 커뮤니티 글 수정·삭제 API

> 글 수정(`PUT /posts/{postId}`)과 삭제(`DELETE /posts/{postId}`)를 만들었다.

- 삭제는 soft delete다. => 글은 안 보이지만 기록은 남긴다.
- 남의 글을 고치려 하면, 카테고리 값이 틀려도 **403이 먼저** 나간다. (아래 결정)

> 동시에 수정하거나, 수정과 삭제가 겹치면?

- `version` 컬럼으로 **낙관적 락**을 건다.
- 수정과 삭제가 겹치면 나중 요청이 409를 받는다. => 지운 글이 수정으로 되살아나지 않는다.
- 테스트는 중간에 별도 트랜잭션을 끼워 넣어서 확인했다.

> 리뷰를 받고 고친 것

- 동시 수정 예외로 바꿔 던질 때, 저장소에서 난 충돌 예외를 **원인(cause)으로 남겼다.** 원인이 남는지 확인하는 테스트도 더했다.
- 원래 예외를 cause로 남기라는 의견은 이 PR과 팀원의 지도 예외 PR 리뷰에서 모두 나왔다.

> 쌓아 올린 PR 정리

- 수정·삭제 브랜치는 작성·조회 PR 위에 쌓은 브랜치였다.
- 작성·조회 PR이 병합된 뒤 `origin/develop` 위로 rebase해서 정리했다.
- 테스트 59개가 통과했고, 커뮤니티 글 이슈의 시나리오 14개를 모두 끝냈다. 이 PR 병합으로 이슈도 닫혔다.

## JPA 컬럼명 네이밍 전략 정리

> `@Column(name)`을 지우고, `application.yml`의 snake_case 네이밍 전략으로 컬럼명을 정한다.

- DB 컬럼명은 바뀌지 않는다.
- 미디어 엔티티는 필드명을 컬럼명에 맞췄다. (`key` → `storageKey` 등) JPQL도 함께 고쳤다.
- `@Table(name)`은 남겼다. (아래 결정)

## 팀원 PR 리뷰

- **산책 도메인·저장소** : 6건을 지적하고 승인했다. 주로 좌표 재전송과 동시 종료 처리를 짚었다.
- **산책 시작·끝 API** : 소수로 온 반려동물 ID가 정수로 잘려서 산책이 생성되는 문제를 짚고 승인했다.
- **관리자 신고 관리 계획** : 커뮤니티 담당으로 의견을 남겼다.
    - 신고 접수와 원본은 커뮤니티가 맡고, 관리자는 입력 포트로 조회·처리한다.
    - 첫 버전의 숨김은 관리자 결정으로만 한다.
- **회원 예외를 공통 기본 예외로** : 지적할 점이 없어서 바로 승인했다.
- **지도 예외를 도메인 예외로** (23시~새벽) : 예외 메시지를 쓰는 위치, 저장 데이터 복원 실패의 응답 코드, 원인 예외 보존을 짚고 승인했다.

## 그 밖에 한 일

- **저장소 설정** : 급한 PR은 관리자가 우회 머지할 수 있게 하고, 머지한 브랜치는 자동으로 지워지게 바꿨다. 협업 규칙에도 적었다. 다만 관리자 우회 머지는 승인뿐 아니라 **필수 CI 검사도 건너뛴다.**
- **전날 작업 병합** : CI 검증 범위 보완(프론트엔드 테스트, PR 이미지 빌드)과 경로 기준 라벨 자동화가 오전에 병합됐다.

## 오늘의 결정

### 1. 수정할 때는 권한부터 확인

- **상황** : 남의 글을 수정하면서 카테고리 값까지 틀리게 보내는 경우, 권한 오류와 카테고리 오류 중 무엇을 먼저 돌려줄지 정해야 했다.
- **무엇으로 바꿨나** : 권한 확인을 카테고리 조회보다 앞에 뒀다.
- **왜** : 권한이 없는 요청에 정보를 주면 안 되니까. => 카테고리 오류가 먼저 나가면, 권한이 없는 사람도 카테고리 값이 맞는지 틀린지 알 수 있다.

### 2. 컬럼명은 네이밍 전략으로, 테이블명은 `@Table`로 남기기

- **상황** : `@Column(name)`을 지우고 네이밍 전략으로 컬럼명을 정하기로 하면서, `@Table(name)`도 지울지 정해야 했다.
- **무엇으로 바꿨나** : `@Column(name)`은 지우고, `@Table(name)`은 남겼다.
- **왜** : 테이블명이 클래스명과 달라서, 빼면 테이블이 바뀐다.
