자바스크립트에서는 함수를 매개변수로 전달할 수 있다. 자바에서는 메서드를 독립적인 값으로 직접 전달하는 대신, 수행할 동작을 인터페이스로 표현하고 구현 객체를 전달한다.

오늘은 정렬을 예시로 기존의 구현 방식부터 람다식, 메서드 참조까지 살펴봤다. 최종적으로는 스프링 코드를 작성할 때 자주 사용하는 Stream API에 동작을 어떻게 전달하는지 이해하기 위한 과정이었다.

# 함수형 인터페이스

> 람다식으로 구현할 동작을 하나로 정할 수 있도록, 추상 메서드를 하나만 가진 인터페이스

`Comparator`는 정렬에 사용할 비교 동작을 `compare()` 메서드로 정의한다. 함수형 인터페이스에는 람다식이 구현할 추상 메서드가 하나만 있어야 한다.

`Comparator`에는 `equals(Object)`도 선언되어 있지만, 이는 `Object`의 공개 메서드와 같은 형태이므로 함수형 인터페이스의 추상 메서드 수를 셀 때 제외한다.

`@FunctionalInterface`를 붙이면 추상 메서드가 하나라는 조건을 컴파일러가 확인한다. 이후 다른 추상 메서드를 추가하면 컴파일 오류가 발생한다.

# 익명 클래스와 람다식

> 익명 클래스는 별도의 클래스 이름 없이, 필요한 위치에서 구현 객체를 바로 만드는 방식이다.

정렬 기준을 전달하기 위해 `Comparator`를 구현하는 클래스를 따로 만들 수도 있다. 한 번 사용할 비교 기준이라면 아래처럼 `sort()`의 매개변수 위치에서 익명 클래스를 만들 수 있다.

```java
names.sort(new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
});
```

람다식을 사용하면 인터페이스의 구현 코드에서 비교 동작에 필요한 부분을 간결하게 표현할 수 있다.

```java
names.sort((a, b) -> a.compareTo(b));
```

매개변수 타입은 문맥에서 알 수 있으면 생략할 수 있다. 매개변수가 하나이고 타입을 적지 않았다면 괄호를 생략할 수 있으며, 본문이 표현식 하나라면 중괄호와 `return`도 생략할 수 있다.

# 메서드 참조와 미리 제공되는 정렬 기준

람다식이 이미 있는 메서드를 그대로 호출한다면 메서드 참조를 사용할 수 있다.

```java
names.sort(String::compareTo);
```

직접 비교 동작을 작성하지 않고, 미리 제공되는 정렬 기준을 사용할 수도 있다.

```java
names.sort(Comparator.reverseOrder());
```

`reverseOrder()`는 역순 정렬 기준을 반환하는 메서드다. 반환되는 객체는 내부적으로 `Comparator`를 구현한 클래스로 만들어져 있다.

# Stream API

> 데이터 소스에서 스트림을 만들고, 처리할 연산을 연결한 뒤 최종 연산으로 결과를 얻는다.

앞에서는 리스트의 `sort()` 메서드에 정렬 기준을 전달했다. Stream API에서는 같은 정렬 기준을 `sorted()`에 전달할 수 있다.

```java
List<String> sortedNames = names.stream()
    .sorted(Comparator.reverseOrder())
    .collect(Collectors.toList());
```

`names.sort()`는 기존 리스트의 순서를 바꾼다. 반면 위 코드는 Stream에서 정렬한 결과를 새로운 리스트로 모으므로, 원본 `names`의 순서는 바꾸지 않는다.

정렬뿐 아니라 조건에 맞는 요소를 고르는 `filter()`, 요소를 다른 값으로 바꾸는 `map()` 등에도 처리할 동작을 람다식이나 메서드 참조로 전달할 수 있다.
