# 오늘의 상황

> 오늘은 인덱스 페이지 구성을 개선하고, 채팅 백엔드를 어떤 방식으로 만들지 고민했다.

- 협업과 문서, 테스트 관리를 위해 이슈 템플릿 수정, 채팅 이슈 나누기, 문서와 e2e 정리를 먼저 진행했다.
- 팀에서는 테스터 인원 제한을 둘지에 대한 논의도 있었다.

# 오늘의 과정

## 인덱스 페이지 구성 바꾸기

### 전체 테스트 목록

- 페이지 나누기를 넣고, 검색·필터·정렬 배치를 바꿨다.
- 결과 수와 빈 상태 문구를 고치고, 게시글 수만 덩그러니 있던 표시도 정리했다.

### 모집 카드

- 카드 아래에 있던 글까지 하나의 카드로 묶었다.
    - 글이 카드 밖에 있으니 옆 테스트와 구분이 잘 안 되고, 한눈에 이해하기 어려웠다.
- 추가 보상 배지는 썸네일 안으로 옮기고, 금액 대신 "추가 보상"으로만 적었다.
- 유형 배지를 넣고, 모집 완료 도장 위치를 정리했다.

### 패널과 배너

> 마감 임박 패널, 공지 슬라이드, 배너가 지금 다 필요할까?

- **마감 임박 패널** : 필요성을 못 느껴서 지웠다.
- **공지 슬라이드** : 공지나 이벤트는 당장 개발하지 않고, 사용자에게 어떻게 전달할지도 아직 정하지 않았다. => 지금은 둘 이유가 없어서 지웠다.
- 배너는 전체 폭 두 장(서비스 소개, 교정 체크리스트)으로 바꿨다.

### 색감

- 라이트 모드에서 색이 이상해서 여러 시안을 받아 봤다.
- 시안 A와 B는 색감만 달랐다. 그중 사용자 입장에서 더 보기 편한 **B로 확정**했다.
    - 흰 바탕에 초록 매트 느낌의 배너
    - 로고 일부를 강조색으로 바꾸고, 파비콘도 바꿨다.

## 채팅 방식 고민

> 채팅 메시지는 어디에 저장하고, 실시간 통신은 어떤 방식으로 할까?

### 실시간 통신 : SSE vs WebSocket

- 아직 결정하지 못했다.
- WebSocket을 쓰자는 쪽의 근거는 파일 전송과 상태 관리였다.
- 채팅에서 가장 중요한 기능은 **읽음 표시**라는 데까지는 정리했다.
- 엔티티 코드를 만들어 컴파일까지 확인했지만, 실시간 방식을 다시 정하기로 하면서 지웠다.

<br/>

## 테스터 인원 제한 논의

> 무료 사용자에게 테스터 인원 제한을 둘까?

- 나는 무료 사용자에게 제한을 좀 더 세게 걸자는 쪽이었다.
    - 구독을 비즈니스 모델로 삼았으니, 구독으로 넘어갈 만한 이유가 이거라고 생각했다.
- 다른 팀 사람들과 강사님의 조언에서는 다른 방향이 나왔다.
    - 인원을 제한하는 게 아니라, **구독으로 제공하는 기능의 가치를 늘리는 쪽**
    - 어떻게 가치를 늘릴지는 더 고민해야 한다.
- 아직 명확하게 정해지지는 않았다.

## 그 밖에 한 일

- **이슈 템플릿** : "사용자 시나리오" 칸을 "시나리오"로 바꿨다. => 사용자가 없는 내부 기능도 쓸 수 있게
- **채팅 이슈 나누기** : 시나리오 하나가 끝까지 동작하는 단위로 하위 이슈를 나눴다.
    - 프론트 연결은 마지막 이슈로 미뤘다. => 로그인 작업이 끝나야 실제 API를 부를 수 있어서
- **e2e 정리** : 448개에서 163개로 줄였다.
    - 화면 모양을 보는 테스트와 중복된 권한 검사는 지우고, 분기 로직·권한·보안 테스트만 남겼다.
    - 시나리오마다 확인 방법 태그(`[테스트]`, `[명령]`, `[직접]`)를 붙였다.

# 배운 점 & 느낀 점

테스터 인원 제한 논의에서 나는 내 의견이 맞다고 생각해서 상대방을 계속 설득했다. 그런데 긴 논의 끝에 다른 팀 사람들과 강사님의 조언을 듣고 나니, 내가 맞지 않을 수 있고 더 나은 방향도 있을 수 있다는 걸 느꼈다.

명확하게 정해진 건 아니지만, 이런 고집을 어느 정도 내려놓을 필요도 있고 좀 더 넓은 시야도 필요하다고 느꼈다.
