# 오늘의 과정

## UI 디자인에서 고민한 점

UI 디자인에서 가장 고민한 건 **AI가 만든 티가 나지 않아야 한다는 것**이었다. 그리고 사용자가 사용할 때 얼마나 편할지도 많이 고민했다.

우선 각 요소가 어떤 데이터를 보여주는지 구분이 잘 되어야 했다. 각 컴포넌트도 구분이 잘 되어야 하고, 그 안에 데이터도 잘 보여야 했다.

## AI 스킬로 디자인 후보 만들기

먼저 인덱스 페이지를 만들고 디자인했다. `ai-desing-skills`로 스케치 UI를 만들고, `impeccable`로 디자인을 입혔다.

`impeccable`은 여러 디자인 후보를 보여줘서, 이걸 팀원들과 공유하면서 UI 컨셉과 사용할 색을 정했다. 그리고 각자 프론트엔드의 어느 부분을 맡을지도 정했다.

## 오늘의 결정

우리 서비스는 테스터가 모집 글을 훑어보다가 마음에 드는 걸 고르는 서비스라, 갤러리 형태로 구성했다. 라이트 모드는 회색 바탕 위에 밝은 종이를 놓은 듯한 느낌으로 디자인했고, 강조색은 에메랄드로 정했다.

컴포넌트를 구분할 때는 그림자 대신 배경의 밝기 차이로 영역을 나눴다. 버튼처럼 누르는 건 알약 모양으로, 내용을 담는 패널과 카드는 모서리가 둥근 모양으로 정했다. 모양만 보고도 누를 수 있는 건지, 데이터를 보여주는 건지 구분하기 쉽게 하기 위해서였다.

## 팀원들과 작업 기준 공유하기

이렇게 만든 결과물은 팀원들과 공유하기 위해 Git에 올렸다.

- 인덱스 페이지
- 디자인 토큰
- plan 양식

5명이 페이지를 나눠 만들다 보니 색도 통일해야 했다. 그래서 색은 `globals.css`에 CSS 변수(디자인 토큰)로 정해 두고, 각 컴포넌트에서는 그걸 사용하게 했다. 그래야 각자 페이지를 만들어도 같은 색을 쓸 수 있고, 나중에 색을 바꿀 때도 한곳에서 바꿀 수 있으니까.

## PR 템플릿 공유

PR 템플릿도 만들어서 공유했다. 그래야 PR 형식이 모두 통일되고, 리뷰하기도 수월하니까.

## 마이페이지 개발

공유 작업 이후에는 마이페이지와 그 하위 페이지를 개발했다.

- 마이페이지 대시보드
- 크레딧 페이지
- 개인정보 수정 페이지
- 출금 페이지

# 배운 점 & 느낀 점

오늘 배운 건 **관점의 차이**였다. 서로 사용자 관점을 고려한다고 생각했는데, 그 관점이 너무 달랐다. 이걸 조율하는 과정이 가장 어려웠다. 서로가 일정 부분 양보하고, 둘의 의견을 합치고 개선하면서 더 좋은 UI 디자인을 만들어 낼 수 있었던 것 같다. 그래서 프로젝트에서 팀원과 소통하는 과정이 정말 중요하다는 걸 많이 느꼈다.

그리고 AI 스킬의 유용성을 느꼈다. 이전에 디자인을 했을 때의 경험으로는 하루 만에 디자인 초안을 모두 만들어 낼 수 없었을 것이다. 그래서 어떤 스킬이 등장하고 어떤 방향으로 발전하는지 계속 확인하고 공부할 필요가 있겠다는 생각을 했다.
