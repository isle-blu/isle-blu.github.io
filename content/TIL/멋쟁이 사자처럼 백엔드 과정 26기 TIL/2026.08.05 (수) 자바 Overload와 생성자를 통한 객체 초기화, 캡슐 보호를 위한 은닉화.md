# Overload

> 같은 이름, 다른 인자를 가지는 함수를 만드는 것을 말한다.

- 상황에 따라 매개변수를 다르게 해 함수를 호출하는 클라이언트 단에서, 다양하게 서비스를 요청할 수 있게 하기 위해 사용된다.

```java
class Calculator {
    // 매개변수 타입이 다름
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    // 매개변수 개수가 다름
    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

- 위와 같이 함수 이름이 같지만, 매개변수 타입이나 개수가 다르게 함수들을 작성할 수 있다.
- 매개변수가 가장 적은 함수가 **"default method"**, 이보다 많은 함수들은 **"overload method"**가 된다.
- 메소드 명이 같다는 것은 행위가 같다는 것을 의미한다. => 즉, 함수 안에서 **다루는 값이 다를 뿐, 연산과 변수는 같다**.
- overload는 많을 수록 호출하는 클라이언트의 선택지가 늘어나기에, 다양할수록 좋다.

# 생성자

> 객체를 생성할 때, 객체를 초기화 해주는 특수목적의 함수

자바에서 제공하는 **객체 초기화**를 위한 함수이다. 하지만 **함수명, return 값이 없어 함수라고 표현하지는 않고**, 생성자라는 별도의 명칭을 사용한다.

생성자도 메소드와 같이 **오버로드가 가능**하다. 넣고 싶은 속성을 인자로 넣어서 오버로드 생성자를 만들 수 있다. 그리고 `this()`의 형태로 오버로드 집중화도 가능하다.

```java
public Exam(){
  // this.kor = 0;
  // this.eng = 0;
  // this.math = 0;

  this(0, 0, 0); // overload 집중화
}

public Exam(int kor, int eng, int math){
  this.kor = kor;
  this.eng = eng;
  this.math = math;
}
```

만약 생성자가 없는 경우, 자바는 자동으로 기본생성자를 만들고, 그 안에 각 타입의 기본 값을 넣는다.

# 은닉화

> 다른 모듈에서 캡슐 내부를 침범하지 못하게 막는 방법

객체는 그 자체로 내부의 속성과 서비스를 책임지는 책임자인데, 다른 곳에서 이 역할을 침범해서는 안된다.

따라서 자바는 각 변수와 메소드에 대해 밖에 공개할 정도를 정할 수 있게 했고, 이것을 **은닉화**라고 한다.

은닉화를 위한 키워드(접근 제어자)는 아래와 같다.

| 제어자                 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 | 공개 범위    |
| ------------------- | ------ | ------ | -------------- | ------ | -------- |
| `private`           | ✅      | ❌      | ❌              | ❌      | 가장 좁음    |
| (default, 접근제어자 생략) | ✅      | ✅      | ❌              | ❌      | 패키지 내부까지 |
| `protected`         | ✅      | ✅      | ✅              | ❌      | 상속 관계까지  |
| `public`            | ✅      | ✅      | ✅              | ✅      | 가장 넓음    |
