# Git branch를 사용하는 이유

> **master(main)에 들어갈 지 여부**를 결정할 수 있기 때문에

- 기능 추가, 버그 수정 등의 개발 시 작업이 잘못되었거나, 기획의 변경 등의 이유로 배포하지 않게될 수 있음.
- 그런데 master(main)과 같은 branch에 작업 시 복구가 어려움 => 별도의 branch를 생성해 작업 공간을 분리하면, master에 merge할 지 검토하고 결정할 수 있음.

---

# Git branch 사용 시 주의사항

1. 수정 사항이 있을 때, commit하지 않으면 **커밋되지 않은 작업물들이 switch하면서 같이 이동**, 버전 관리가 매우 꼬이게될 수 있음. => 커밋을 하거나, `git stash` 명령어를 통해 임시저장하고 branch 변경
2. merge까지 완료된 branch 관리 => 취향의 영역이지만, **해당 branch를 삭제하는 것을 권장**, branch가 많아지며 복잡해지는 것을 예방
3. branch 명 결정 시 주의사항 **사람 이름으로 branch 생성 X** => 같은 기능을 여러 명이 동시 개발, 수정하며 충돌이 발생할 수 있음 => 완료된 branch를 파악하기 어렵고 현재 진행사항에 대해 검토할 수 없어 branch 정렬이 어려움.

# Git 협업

> Git은 github, gitlab과 같은 **Git server(원격 저장소)**를 통해 개발자 들끼리 코드와 버전을 공유하고 협업할 수 있다.

![이미지](https://cdn.likelion.net/classroom/kdt-backendj-26th/til/ae37a2e5-6d06-450b-b103-a8075bdc9579.png)

- 개인은 인터넷을 통해 자신의 git repository를 Git server에 올리거나(`git push`), Git server있는 원격 저장소(Bare repository)를 내려받을 수 있다.(`git clone`, `git pull`) => 코드, 버전 관리 기록 등을 공유하고 커밋 이력 등을 백업하는 용도로도 사용할 수 있다.

## 원격 저장소에 업로드

> 원격 저장소에 연결하고, 업로드하는 것

### 1. 원격 저장소에 연결

1. `git remote add <원격 저장소의 이름(거의 대부분 origin)> <원격 저장소 URL>` 명령어를 통해 원격 저장소에 연결한다.
2. 연결 없이 업로드 명령어인 `push`를 사용할 경우 **(Error)**

- 아래와 같이 목적지를 못찾겠다는 에러와 함께, `git remote add` 명령어를 안내한다.


    ```bash
    # 예시
    user@computer:~/my-project$ git push
    fatal: No configured push destination.
    Either specify the URL from the command line or configure a remote repository using
    
        git remote add <name> <url>
    
    and then push using the remote name
    
        git push <name>
    ```
   

### 2. 원격 저장소에 업로드

- `git push`만 입력한 경우 **(Error)**
<br/>

    
    ```bash
    # 예시
    user@computer:~/my-project$ git push
    fatal: The current branch main has no upstream branch.
    To push the current branch and set the remote as upstream, use
    
        git push --set-upstream origin main
    ```

<br/>

-  위와 같이 현재 브랜치가 `upstream branch`가 아니라고 언급한다.
- 해결을 위해 `git push --set-upstream origin main` 명령어를 안내한다.
    > `upstream branch`? **로컬 저장소의 브랜치와 직접적으로 연결**된 원격 저장소의 브랜치 이 둘이 연결되면 두 브랜치는 **추적(tracking)** 관계가 되며, push 명령어 뒤에 별도의 옵션이나 브랜치 명이 없어도 추적 관계에 있는 로컬 저장소 브랜치의 변경사항과 커밋 메시지가 업로드된다.
    


- `git push --set-upstream origin main(master)`을 입력한 경우
    
    - main(master) 브랜치가 원격 저장소의 main(master) 브랜치와 연결되며, 업로드가 진행된다.

## 원격 저장소에서 가져오기

> 원격 저장소를 로컬로 복제하거나, 원격 저장소에 변경사항을 로컬로 가져오는 것

### 원격 저장소 복제

- `git clone <원격 저장소 URL>` : 원격 저장소를 로컬에 복제
<br/>
    
    ```bash
    # 예시
    user@computer:~/Desktop$ git clone https://github.com/username/team-project.git
    Cloning into 'team-project'...
    remote: Enumerating objects: 154, done.
    remote: Counting objects: 100% (154/154), done.
    remote: Compressing objects: 100% (98/98), done.
    remote: Total 154 (delta 45), reused 130 (delta 30), pack-reused 0 (from 0)
    Receiving objects: 100% (154/154), 48.20 KiB | 3.21 MiB/s, done.
    Resolving deltas: 100% (45/45), done.
    
    user@computer:~/Desktop$ cd team-project/
    user@computer:~/Desktop/team-project$ #git이 관리하는 복제된 저장소
    ```

<br/>

- `git pull` : 연결된 원격 저장소의 변경 사항 가져오기
<br/>

    ```bash
    # 예시
    user@computer:~/Desktop/team-project$ git pull
    remote: Enumerating objects: 7, done.
    remote: Counting objects: 100% (7/7), done.
    remote: Compressing objects: 100% (4/4), done.
    remote: Total 4 (delta 2), reused 0 (delta 0), pack-reused 0 (from 0)
    Unpacking objects: 100% (4/4), 385 bytes | 385.00 KiB/s, done.
    From https://github.com/username/team-project
       abcdef1..1234567  main       -> origin/main
    Updating abcdef1..1234567
    Fast-forward
     src/main/java/controller/UserController.java | 12 +++++++++---
     src/main/resources/application.properties    |  2 +-
     2 files changed, 10 insertions(+), 4 deletions(-)
    ```

<br/>

- `git pull`은 `git fetch`와 `git merge`가 합쳐진 명령어다.
        - `git fetch` : 원격 저장소의 최신 변경사항을 가져오고, 로컬 작업 공간에 병합하지 않음 -> 내부의 원격 저장소 추적 브랜치(origin/main)만 최신화
<br/>
            
            ```bash
            # 예시
            user@computer:~/Desktop/team-project$ git fetch origin
            remote: Enumerating objects: 5, done.
            remote: Counting objects: 100% (5/5), done.
            remote: Total 3 (delta 1), reused 0 (delta 0), pack-reused 0 (from 0)
            Unpacking objects: 100% (3/3), 340 bytes | 340.00 KiB/s, done.
            From https://github.com/username/team-project
               abcdef1..7890xyz  main       -> origin/main
            ```

<br/>

- `git merge` : `fetch`로 가져온 변경사항이 저장된 원격 저장소 추적 브랜치(origin/main)을 로컬 브랜치와 병합하고 반영

<br/>

		```bash
            #예시
            user@computer:~/Desktop/team-project$ git merge origin/main
            Updating abcdef1..7890xyz
            Fast-forward
             src/main/java/controller/UserController.java | 2 +-
             1 file changed, 1 insertion(+), 1 deletion(-)
		```

<br/>

## Git 협업 관련 명령어 정리

| 명령어                                      | 동작                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------- |
| git remote add <원격 저장소의 이름> <원격 저장소 URL> | git server에서 생성한 원격 저장소와 연결, 원격 저장소 이름은 일반적으로 "origin"사용                  |
| git push                                 | 내 repository의 커밋된 작업을 원격저장소에 업로드                                          |
| git push --set-upstream origin main      | main 브랜치를 원격 저장소의 기본 브랜치로 설정, 이후 push할 때 별도의 브랜치를 적지 않으면 main branch에 업로드 |
| git clone <원격 저장소 URL>                   | 원격저장소의 repository를 내 pc로 복제                                               |
| git clone <원격 저장소 URL> <폴더 이름>           | 원격저장소의 repository를 내 pc에 지정한 폴더 이름으로 저장                                   |
| git pull                                 | 원격 저장소에 업로드된 수정사항들을 내 pc의 repository 현재 branch에 병합                        |

> 왜 origin을 사용할까? origin은 Git에서 기본값으로 사용하는 관례적인 이름으로, 대다수의 사람이 기본값으로 사용하기 때문에 origin을 사용한다.
