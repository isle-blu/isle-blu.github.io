# 오늘의 상황

> 오늘은 팀원들이 올린 PR을 리뷰하고, 내 작업으로 구독 관리 페이지를 만들었다.

어제 페이지를 나눠 만들기 시작했고, 오늘은 팀원들이 올린 PR이 들어와서 리뷰를 진행했다. 그리고 어제 남겨 둔 구독 페이지를 이어서 만들었다.

# 오늘의 과정

## PR 리뷰에서 본 것

리뷰할 때는 크게 네 가지를 봤다.

- 디자인 토큰을 잘 사용하고 있는지
- 화면과 코드에서 문제가 생기는 부분은 없는지
- 화면에서 빠진 부분은 없는지
- UI에서 개선할 부분은 없는지

### 코드에서 생기는 문제

회원 상세 페이지에 들어갈 때 `instant-shell-url-data` 진단이 발생했다. 원인은 `await params`를 먼저 실행한 뒤 `<Suspense>`를 반환하고 있는 구조였다. URL 데이터를 읽는 부분이 Suspense 밖에 있으니, 아래에 있는 Suspense가 그보다 먼저 실행된 대기를 처리하지 못한다.

```tsx
// 문제가 된 구조
export default async function Page({ params }) {
  const { userKey } = await params; // Suspense 밖에서 대기
  return <Suspense fallback={<AdminShellSkeleton />}>...</Suspense>;
}
```

그래서 `params` Promise를 자식 컴포넌트로 넘기고, `<Suspense>` 안의 자식에서 `await params`와 회원 키 검증을 하도록 바꾸자고 제안했다. 기존 `AdminShellSkeleton`도 그대로 활용할 수 있어서 이 방식이 자연스러워 보였다.

수정 후에는 회원 목록 → 회원 상세로 이동할 때 진단이 사라지는지, 없는 회원 주소로 들어갔을 때 맞춤 404가 유지되는지도 확인해 달라고 남겼다.

모집 취소 상세 페이지도 같은 구조여서, 같은 방법으로 수정하자고 코멘트를 남겼다.

### 화면에서 개선할 부분

직접 화면을 확인하면서 개선하면 좋겠다고 느낀 점도 남겼다.

- **디자인 규칙** : '지금 확인할 일'의 링크에 강조색을 쓰고 있어서, `DESIGN.md`의 일반 링크 색상 규칙에 맞춰 달라고 했다.
- **돌아가는 동선** : 프로젝트 상세에서 '내 프로젝트' 목록으로 돌아가는 버튼이 없어서 브라우저 뒤로 가기를 써야 했다. 상단에 돌아가기 링크를 추가하자고 했다.
- **카드 구분** : 다크 모드에서 프로젝트 카드들이 모두 검은 배경으로 이어져서 카드끼리 구분이 잘 안 됐다. 기존 디자인 토큰으로 배경 차이나 테두리를 보완하자고 했다.
- **지표 변경** : 전체 프로젝트의 진행 상황을 보는 영역이라, '확정된 테스터'와 '받은 피드백' 대신 '모집 완료'와 '테스트 중'을 보여 주자고 제안했다. 이름만 바꾸는 게 아니라 모든 프로젝트의 모집 건을 상태별로 집계해서 n건으로 표시하는 방식이다.

## 구독 관리 페이지 개발

우선 어떤 내용이 들어가야 하는지부터 고민했다.

그리고 무료를 쓰는 사람과 구독한 사람의 UI를 어떻게 다르게 할지 정했다. 구독한 사람에게는 구독에 대한 정보와, 구독이 만료되면 어떤 차이가 생기는지를 넣어 줬다. 요금제 안내에는 각자 어떤 요금제를 사용 중인지 배지로 표시했다.

## 오늘의 결정

- **상황** : 구독 관리 페이지에 구독 요금제 안내가 들어가도 되는지 고민했다.
- **무엇으로 바꿨나** : 요금제 안내를 간략하게 넣기로 했다.
- **왜** : 지금은 목업 데이터로 요금제가 하나뿐이지만, 나중에 요금제를 비교할 수도 있고, 자기가 사용하는 요금제의 한도가 어디까지인지 보여 주기 위해서였다.

다만 그냥 자기 요금제에 대해서만 정리해서 보여 줘도 될 것 같다. 이건 추후 고민할 점으로 남겨 뒀다.

## 수정한 부분

- UI에 여백이 많아서, 카드 안 본문의 글자 크기와 배치를 수정했다.
- 남은 잔여량 같은 걸 표시해 주는 바를 추가했다.

# 배운 점 & 느낀 점

가장 문제였던 건 **AI가 내 말을 임의로 해석해서 작업을 진행한다는 점**이었다. 나는 진행하라고 말한 적이 없는데 작업을 진행해 버렸다.

나도 모르는 사이에 작업을 진행하고 커밋까지 해 버리면 문제가 생긴다. 지금은 push와 PR을 규칙으로 막아 둬서 다행이었지, 안 그랬으면 PR까지 올라갔을 것이다.

그래서 이걸 막는 방법을 고안해야겠다고 느꼈다. 작업은 내가 제어할 수 있어야 하니까.
