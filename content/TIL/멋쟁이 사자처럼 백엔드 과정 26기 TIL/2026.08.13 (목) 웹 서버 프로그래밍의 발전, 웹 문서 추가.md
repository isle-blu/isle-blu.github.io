# 웹 서버 프로그래밍의 발전

## Stand Alone(독립형) Application

- 데이터를 각자 관리하는 방식
- 데이터 공유, 동기화 문제 발생 => 분산형 Application의 필요성 대두

## Enterprise(기업형) Application

- 대부분 분산형 Application
- Server - Client 방식으로 데이터 공유
- 버전 업그레이드 및 업데이트 시 기존 파일 삭제 및 새 버전으로 재설치 => 오래 걸리고, 업데이트마다 예기치 못한 문제가 다수 발생

## Enterprise(기업형) Web Application

- 기존 설치형 방식에서 웹 문서로 전달하는 방식 고안
- 웹 제공자(Web Server)를 통해 정적 웹 문서 처리 및 전달
- html / css 문서 자체를 만들어 배포 => Web Server, 개발 환경, 브라우저만 있으면 웹 문서로 데이터를 쉽게 전달 가능
- 동적 콘텐츠 처리를 위해, Web Application Server(WAS)의 등장
    - Servlet을 통해 클라이언트 요청에 맞게 동적 처리 및 응답

> Tomcat의 두 기능

1. 독립적인 서버(Web Server)를 띄워 정적인 문서 배포
2. 임베디드 톰캣으로 톰캣을 코드로 띄우고 동적으로 서블릿 관리

# Jasper

> 정적 문서인 HTML을 Servlet으로 바꿔주는 도구

Servlet 클래스에서 직접 html을 작성하려면, 너무 귀찮고 부담스러운 작업이 필요하다. 하지만 Jasper는 이 작업을 대신해줄 수 있다.

배포하고자 하는 html 문서의 확장자를 `.jsp`로 변경하고 컴파일하면 자동으로 자바 파일과 클래스 파일을 생성하게 된다. 내부를 확인하면 html 문서의 내용을 자동으로 `write`해 놓은 것을 볼 수 있다.
