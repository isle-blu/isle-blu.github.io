# 스프링 3계층 구조와 폴더 구성

> 기능을 컨트롤러, 서비스 등의 역할에 따라 나누고, 관리자 기능은 각 계층의 `admin` 패키지에 모아 관리한다.

메뉴 기능을 예로 들면, 일반 메뉴와 관리자 전용 메뉴의 컨트롤러와 서비스가 각각 존재한다.

```text
com.isleblu.backend
├── controller
│   ├── admin
│   │   └── MenuController.java
│   └── MenuController.java
├── dto
├── entity
└── service
    ├── admin
    │   └── MenuService.java
    └── MenuService.java
```

관리자 기능을 파일명으로만 구분하는 것보다 `admin` 패키지로 묶어두면, 관련 기능이 어디에 있는지 폴더 구조에서 확인할 수 있다.

## 같은 이름의 클래스와 스프링 빈

> 패키지가 다르면 자바 클래스 이름은 같아도 되지만, 스프링 빈 이름까지 자동으로 구분되는 것은 아니다.

일반 메뉴와 관리자 메뉴에 각각 `MenuController`, `MenuService`를 만들 수 있다. 하지만 두 클래스를 모두 스프링 빈으로 자동 등록하면 기본 빈 이름이 `menuController`, `menuService`로 같아져 충돌할 수 있다.

이를 해결하려면 관리자용 빈에 `adminMenuController`, `adminMenuService`처럼 이름을 직접 지정하거나, 클래스 이름을 `AdminMenuController`, `AdminMenuService`로 구분해야 한다.

# 카페 앱 WBS 작성

> 카페 앱에 필요한 기능을 작업 단위로 나누고, 각 작업에 페이지 URL과 API URL을 연결했다.

오후에는 회원, 메뉴, 주문, 결제, 배달 등의 기능을 정리하는 WBS를 만들었다. 작업마다 코드를 붙이고, 사용자 기능인지 관리자 기능인지도 구분했다.

메뉴 기능에서는 관리자의 메뉴 등록·수정·조회·삭제와 사용자의 메뉴 조회를 별도 작업으로 나눴다. 예를 들어 관리자 메뉴 등록에는 페이지 URL `/admin/menus/create`와 API `POST /api/admin/menus`를 연결했다.

같은 메뉴를 다루더라도 **누가 어떤 작업을 하는지**에 따라 필요한 페이지와 API가 달라진다는 것을 확인했다.
