이번 포스팅은 스프링에서 직렬화와 역직렬화가 어떻게 이뤄지는지에 대해 정리하고자 한다.


## 직렬화 vs 역직렬화
먼저 직력화와 역직렬화가 뭔지 알아볼 것이다. 직렬화와 역직렬화는 **데이터를 저장하거나 전송하기 위해 사용하는 개념**이다.

<br/>

### 직렬화
> 객체나 데이터를 ==저장하거나 전송할 수 있도록 바이트(byte)나 문자열 같은 형식으로 변환==하는 과정이다.

우리가 프로그래밍을 하면서 다루는 데이터는 메모리 안에서 구조적으로 존재한다. 이것을 파일로 저장하거나, 네트워크를 통해 전송하려면, 바이트 형태나, 문자열 현태로 변경이 필요하다.

<br/><br/>

### 역직렬화
> 직렬화한 데이터를 ==다시 원래의 객체나 구조로 복원==하는 과정이다.

위에서 말한 것처럼 직렬화를 하게되면 일련의 바이트나 문자열의 형태가 된다. 이것을 다시 프로그램에서 다루기 위해선 원래의 모습으로 돌려놔야 한다. 이 과정을 역직렬화라고 하는 것이다.


<br/><br/>

### 사용 이유
직렬화 / 역직렬화를 사용하는 이유가 뭘까? 바로 ==서로 다른 시스템 간에 데이터를 주고받기 위해서다.==

예를 들어 자바는 데이터 타입을 원시 타입(Primitive Type)과 참조 타입(Reference Type)으로 구분한다.

둘 중 참조 타입은 객체의 메모리 주소값을 갖는 타입이다. 아래 그림을 보면 User 객체는 reference 값을 갖고있는 것을 확인할 수 있다.

![[직렬화역직렬화.png]]

따라서 자바 객체의 형태로 그대로 전송하면 클라이언트는 주소값만 받지 해당 주소값에 있는 데이터는 받을 수 없다.  따라서 JSON가 같은 방식으로 바꿔서 전달하는 것이다.

>[!tip] 참고사항
>- 위에선 객체를 네트워크로 전달하는 것처럼 설명했지만, 실제로 객체 그대로 네트워크에 보낼 수는 없다. 그래서 직렬화/역직렬화가 반드시 필요하다.
>- 이외에도 데이터를 저장(캐시, 파일)하거나 복원 시에도 직렬화/역직렬화를 사용한다.


<br/><br/><br/>


## 스프링에서 직렬화 / 역직렬화
스프링은 다양한 곳에 직렬화, 역직렬화가 사용된다. 어디에서 어떤 방식으로 사용되는 지 알아보자.

<br/>

### 1. HTTP 요청 / 응답 처리 (JSON  ⇄  객체)
스프링에서 직렬화 / 역직렬화를 생각하면 가장 많이 떠올리는 게 HTTP Api 요청 시 직렬화와 역직렬화다. 스프링에서 HTTP api 요청과 응답을 처리할 때, JSON과 객체를 서로 변환하며 사용한다.

여기서 사용하는 라이브러리가 **Jackson**이다.

>[!faq] Jackson이란?
>- **Java용 JSON 처리 라이브러리**로 objectMapper라는 클래스를 중심으로 직렬화/역직렬화 수행
>- 스프링 부트는 기본으로 ==Jackson이 포함되어 있어 `@RequestBody`, `ResponseBody`, `RestController` 등에서 자동으로 동작==한다.

<br/>

#### 직렬화(Response)
클라이언트로 보내야하는 Java 객체를 JSON으로 변환하는 과정이다.

```java
@RestController
public class UserController {
	@GetMapping("/user")
	public User getUser() {
	    // Java 객체를 JSON으로 직렬화하여 클라이언트에게 반환
	    return new User("Alice", 25);
	}
}
```

`@ReatController` 는 Jackson이 자동으로 동작하며 Java 객체를 JSON 문자열로 변환한다. 
여기서 주의할 사항은 직렬화 시에 직렬화
하는 class에 getter 매서드가 반드시 있어야 한다는 점이다. 

`@Controller`의 경우 view를 반환하는 것이 기본이다. 따라서 `@ResponseBody` 를 붙여야 JSON 직렬화가 적용될 수 있다. 

<br/>

>[!check] getter가 있을 때
>```java
>public class User {
>    private String name;
>    
>    public User(String name) {
>        this.name = name;
>    }
>
>    public String getName() {  // ✅ getter 존재
>        return name;
>    }
> ```
>
>```java
>User user = new User("Alice");
>String json = objectMapper.writeValueAsString(user); //Jackson 동작
>System.out.println(json);
>```
> 위처럼 getter가 존재하는 경우  아래와 같이 제대로 JSON이 출력된다.
> 
> JSON 출력 : 
>```json
>{
>  "name": "Alice"
>}
>```

<br/>

>[!fail] getter가 없을 때
>```java
>public class User {
>    private String name;
>    
>    public User(String name) {
>        this.name = name;
>    }
>	// ❌ getter 없음
>}
> ```
>```java
>User user = new User("Alice");
>String json = objectMapper.writeValueAsString(user); // Jackson 동작
>System.out.println(json);
>```
> 위처럼 getter가 존재하지 않는 경우, Jackson이 필드 값을 읽지 못해 아래처러무 JSON으로 변환하지 못한다.
>
>JSON 출력:
>```json
>{}
>```

#### 역직렬화(Request)
요청 시 받은 JSON을 Java 객체로 변환하는 과정이다. 

```java
@RestController
public class UserController {
    
    @PostMapping("/user")
    public String createUser(@RequestBody User user) {
        // JSON 데이터를 Java 객체 User로 역직렬화
        return "User name: " + user.getName();
    }
}
```

`@RequestBody`가 JSON을 Java 객체로 역직렬화 해준다. 

<br/><br/>

### 2. 이외 직렬화 / 역직렬화 사용 사례
#### 파일 저장 및 복원 (Persistence)
자바 객체를 파일을 저장하거나, 다시 불러올 때 사용하는 사례이다. 해당 기능은 스프링이 아닌 자바 자체 기능을 사용한다.

```java
// 저장 (직렬화)
ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("user.ser"));
out.writeObject(new User("Alice", 25));
out.close();

// 불러오기 (역직렬화)
ObjectInputStream in = new ObjectInputStream(new FileInputStream("user.ser"));
User user = (User) in.readObject();
in.close();
```

클래스의 경우 `Serializable` 인터페이스를 구현해야한다.

<br/><br/>

#### 캐시 저장소(Redis 등)
자바 객체를 캐시에 저장할 때 문자열/JSON/Binary로 직렬화 한다.

```java
@Cacheable("users")
public User getUserById(Long id) { ... }
```

Redis는 캐시는 상당히 많이 사용되기 때문에 추후에 다룰 수 있다면 별도로 다루도록 하겠다.

<br/><br/>

#### 메시지 큐 시스템(Kafka 등)
객체를 메시지로 전송할 때 직렬화가 필요하다.

```java
// 직렬화: 객체 → JSON
String json = objectMapper.writeValueAsString(order);
kafkaTemplate.send("orders", json);

// 역직렬화: JSON → 객체
@KafkaListener(topics = "orders")
public void consume(String message) {
    Order order = objectMapper.readValue(message, Order.class);
}
```
